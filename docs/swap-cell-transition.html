Under the hood: scripts, capacity & pricing

Pool State. Lock args: 01 || poolId. Type args: 00 || poolId. Both scripts and the poolId stay the same; the new state records the updated reserves, increments the nonce, and keeps total LP unchanged. Each output has a new OutPoint.

Reserve Cell. The role-2 pool lock binds the same poolId. The official SWAP xUDT type validates token conservation. Its data holds the actual token balance; the Pool State records the matching reserve.

CKB capacity. The State Cell holds a 500 CKB storage base plus the native CKB reserve. The SWAP Reserve Cell keeps 200 CKB. The wallet separately funds the illustrated 200 CKB receive Cell and network fees, with remaining CKB returned as change. Receive Cell capacity stays under the user's control.

Exact-input pricing · 8 decimal places
SWAP out = floor(ΔCKB × 997 × SWAP reserve
/ (CKB reserve × 1000 + ΔCKB × 997))
Calculated in integer base units. The full CKB input enters the reserve; the 0.3% pool fee remains in the pool.

One transition, one transaction. Input and output groups are validated together. Two swaps cannot both consume the same live State Cell: a competing transaction must rebuild against the updated pool state.
